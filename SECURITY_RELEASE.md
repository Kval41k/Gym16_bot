# Усиление безопасности — 28.10.2026

## Сделано

- Права администратора выдаются только числовым `ADMIN_IDS` (`ADMIN_USERNAME` игнорируется). Перед публикацией проверить ID владельца в Render Environment.
- Авторизация Telegram действует 2 часа. При 401 Mini App предлагает скопировать текст незавершённых форм перед повторным открытием. Копия хранится в sessionStorage отдельно для каждого пользователя, без токенов и файлов, не подставляется автоматически в другие записи. Восстановление сессии между разными WebView зависит от Telegram, поэтому предлагается явное копирование.
- Данные старосты получают `Cache-Control: no-store`. Скрипты вынесены из HTML; фиксированный реестр событий не использует eval/Function. CSP запрещает inline-скрипты и inline-обработчики. Inline-стили пока разрешены.
- Новые картинки принимаются через загрузку; произвольные внешние URL отклоняются. Старые сторонние изображения не загружаются. Аватары допускаются с указанных доменов Telegram. Ссылки на учебные источники остаются доступными.
- Квоты изображений: 100 МБ на пользователя, 1024 МБ суммарно; требуется 128 МБ свободного диска. Старые локальные загрузки учитываются по фактическому размеру. Квоты проверяются под блокировкой БД. Неиспользуемые загрузки старше 7 дней удаляются вместе с метаданными; прикреплённые изображения сохраняются. На небольшом сервере стоит уменьшить общую квоту.
- `/api/health` — доступность процесса; `/api/ready` — проверка БД, диска и при включении S3 доступности бакета. Свежесть локальной/внешней копии видна отдельно: устаревшая копия не вызывает бесконечные перезапуски.
- Alembic baseline принимает существующую схему без удаления данных и создаёт новую с нуля. Следующие изменения оформлять отдельными ревизиями, baseline не изменять. Откат baseline запрещён; используется проверенная резервная копия. Запуск приложения выполняет `upgrade head`.
- GitHub Actions запускает изолированные сценарии, синтаксис, воспроизводимость CSS, аудит зависимостей и отдельные сценарии на PostgreSQL. `python scripts/check_all.py` запускает локальные проверки; PostgreSQL требует отдельного одноразового сервиса CI.
- Резервные архивы проверяются по ZIP CRC и формату. Создание сериализовано файловой блокировкой, используются уникальные временные файлы и атомарная замена. Сбой бэкапа больше не прерывает обработку уведомлений в этом цикле. Исключения журналируются с очисткой секретов.

## Подключение постоянного хранения

Код подключения готов; создание аккаунтов, оплата, перенос рабочих данных и включение внешних сервисов не выполняются автоматически. Пока реквизиты не заданы, локальное хранение остаётся временным.

1. Выбрать постоянно работающий сервер и постоянную PostgreSQL либо постоянный диск для SQLite. Это отдельное решение от хранения файлов: внешний бакет не устраняет сон сервера.
2. Скачать и проверить текущий архив **до** переключения хостинга. Остановить изменения на время финального переноса. Целевая БД и папка загрузок должны быть пустыми.
3. Задать `DATABASE_URL` и восстановить `python backup_restore.py ARCHIVE.zip --apply` в пустую целевую БД/папку. Затем запустить `python -m alembic upgrade head`. Проверить классы, роли, новости, комментарии и таблицы старосты.
4. Создать **закрытый** S3-совместимый бакет (поддерживаются S3/R2), реквизиты сохранить в Environment сервера. У токена должны быть только необходимые права чтения/записи/удаления для `media/`, `backups/` и листинга этих префиксов. Бакет не открывать в интернет; изображения выдаёт приложение после авторизации.
5. Для существующих локальных фото: сначала `python scripts/migrate_media.py` (проверка), затем `--apply` (копирование и проверка чтением). Исходники не удаляются. Только после успешного копирования включить `S3_MEDIA_ENABLED=true`. Не включать его для неперенесённых файлов.
6. Сгенерировать отдельный ключ: `python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'`. Сохранить его в `BACKUP_ENCRYPTION_KEY` и отдельно от бакета в защищённом месте. Без ключа восстановить архив невозможно. В чат и Git ключ не отправлять.
7. Включить `BACKUP_REMOTE_ENABLED=true`. Архив шифруется Fernet до отправки, скачивается обратно, расшифровывается и проверяется. После успешной проверки выполняется ротация (30 дневных копий по умолчанию). Шифрование не заменяет разграничение доступа к бакету.
8. Скачать внешний `.zip.fernet` и выполнить учебное восстановление на отдельном пустом экземпляре: `python backup_restore.py COPY.zip.fernet --apply` с тем же ключом в окружении. Проверить данные и медиа, а не только завершение команды. Такое восстановление проверено локально с имитацией S3; реальное внешнее хранилище требует отдельной проверки после подключения.
9. Включить `REQUIRE_PERSISTENT_STORAGE=true` после проверки настроек. Для диска Render задать `RENDER_DISK_PATH` и разместить БД/файлы внутри него. Это проверка конфигурации, не доказательство надёжности провайдера.

Локальные ZIP доступны администратору и могут быть скачаны без шифрования: хранить их приватно. Ключи, credentials и `.env` в бэкап не включаются. Отправка в стороннее хранилище начинается только после включения настроек.

Основа интеграций: [Alembic](https://alembic.sqlalchemy.org/en/latest/cookbook.html), [официальный SDK S3](https://docs.aws.amazon.com/boto3/latest/reference/services/s3.html).
