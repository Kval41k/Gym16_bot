# Обзор проекта и проверка изменений — 25.10.2026

## Назначение и устройство

Это школьное приложение для 11-х классов гимназии №16: расписание с профилями и временем занятий, школьная лента с модерацией, реакции и комментарии, материалы ЕГЭ и личный прогресс. Профиль связан с Telegram. Администратор управляет публикациями, пользователями, расписанием, материалами и журналом действий; есть экспорт и восстановление резервных копий.

FastAPI обслуживает API и статический интерфейс HTML/JavaScript. aiogram запускает бота в том же процессе. SQLAlchemy работает с SQLite или PostgreSQL. Настройки и ключи приходят из окружения. `timetable.py` объединяет время карточек, текущий статус и напоминания; `data_updates.py` применяет проверенные версии расписания. `audit.py` записывает изменения в одной транзакции с данными. `features.py` содержит персональные настройки, прогресс, администрирование расписания, уведомления и резервные копии.

Для установленной предыдущей версии применяется точечная коррекция с сохранением остальных ручных изменений. Перед ней создаётся локальная копия расписания. У 11Б сохраняется сообщение об отсутствии загруженного расписания.
- В профиле появились светлая, тёмная и автоматическая темы. Автоматическая получает режим и безопасные значения палитры Telegram, реагирует на `themeChanged`. Выбор сохраняется в БД и локально отдельно для каждого Telegram ID. За пределами Telegram автоматический режим ориентируется на тему системы. Настройка темы не сбрасывает напоминания.
- Автор может редактировать собственный комментарий. Текст изменяется на месте, появляется отметка, история попадает в административный журнал. Ревизия и блокировка транзакции защищают от перезаписи параллельного изменения. Администратор не может выдавать своё редактирование за слова другого пользователя.
- При переключении разделов сбрасывается прокрутка: начало новой страницы не остаётся скрытым.

## Проверка безопасности и устранённые проблемы

1. Лента, комментарии, учебные материалы и изображения требуют действительную подпись Telegram и активный аккаунт. Недостаточно передать произвольный ID. Расписание остаётся общедоступным.
2. Фото ожидающей модерации новости доступны автору и администраторам. Обычный пользователь получает доступ после одобрения. Прокси Telegram не выдаёт произвольный файл бота по одному `file_id`. Заголовок авторизации передаётся при загрузке изображения, не помещается в URL.
3. Загружаемые изображения действительно декодируются и перекодируются; убираются метаданные, отклоняются поддельные сигнатуры, SVG и чрезмерные размеры. Ограничены байты запроса, файла и количество пикселей. HEIC требуется предварительно преобразовать в JPEG.
4. Профиль не принимает произвольную клиентскую фотографию вместо подписанной Telegram. Исправлено небезопасное включение адреса аватара в HTML. Пользовательский текст экранируется в интерфейсе; тестовый HTML в комментарии отображается буквально.
5. Проверяются профиль класса, номера заданий, длины текста, протоколы ссылок, повторяющиеся поля подписи, срок авторизации и предел Telegram ID. CSV-экспорт нейтрализует формулы в текстовых ячейках.
6. Удаление новости или материала не удаляет картинку, ещё используемую другой записью. Файловые пути ограничены допустимым каталогом, имена выдаются сервером, символьные ссылки не обслуживаются.
7. Ответы с персональными данными запрещают кеширование. Добавлены CSP, `nosniff`, запрет передачи referrer и ненужных разрешений браузера. Tailwind собирается локально; исполняемый сторонний CDN сборки удалён.
8. Секреты и подписанные параметры скрываются в сообщениях и исключениях Python logging. Действующих секретов в текущих отслеживаемых файлах не обнаружено. Найденный в старой истории токен проверен через Telegram: HTTP 401, он уже отозван. Локальная `.env` содержит старую копию; она не включается в Git или резервные копии приложения.
9. Runtime-зависимости зафиксированы через `requirements.lock.txt`. `pip-audit` не нашёл известных уязвимостей в проверенном окружении. Исправлена зависимость CSS-сборки `postcss-selector-parser`; `pnpm audit` — 0 уязвимостей. Основание: https://github.com/advisories/GHSA-rj75-hqrm-r3gf.

### Проверки и границы результата

Локальные проверки используют Python 3.12, отдельные временные базы, фиктивные подписи и не отправляют реальные сообщения. Выполняются:

```sh
python tests/check_features.py
python tests/check_calendar_sync.py
python tests/check_security_and_comments.py
node tests/check_theme.cjs
pnpm run build:css
```

Покрываются изоляция аккаунтов и прав администратора, подпись и срок Telegram-авторизации, запрет доступа заблокированных пользователей, редактирование и конфликты комментариев, журнал и откат транзакций, темы и частичные настройки, приватность фотографий и обработка некорректных файлов, ограничения размера запросов (также без Content-Length), редактирование расписания и конфликты ревизий, обе миграции календаря, совпадение времени карточек/статуса/напоминаний, отсутствие повторных отправок при неопределённом результате, прогресс ЕГЭ, экспорт и восстановление копии с отказом перезаписать существующую БД.

Интерфейс дополнительно проверен в браузере на ширине 390 px: обе темы, сохранение выбора, собственный комментарий и буквальное отображение HTML, защищённая фотография.

Это проверка кода и выбранных сценариев, а не гарантия отсутствия всех уязвимостей. PostgreSQL-ветка, инфраструктура Render/Telegram и все реальные устройства не проходили отдельного полного тестирования. Аудит пакетов не проверяет все уязвимости самого интерпретатора и ОС. Отдельного нагрузочного теста и независимого пентеста не было.

## Что остаётся важным

- **Сохранность данных.** Текущий бесплатный Render с локальной SQLite, uploads и backups не гарантирует сохранение файлов при пересоздании сервиса. Локальная резервная копия на том же временном диске исчезает вместе с ним. Для постоянной работы нужны внешняя PostgreSQL, постоянное хранилище изображений и копии вне сервиса. Это отдельная настройка инфраструктуры; платные ресурсы не создавались.
- **Доступ школьников.** Подпись подтверждает Telegram-аккаунт, но пользователь сам выбирает класс. Приложение пока не подтверждает принадлежность гимназии. Если лента должна быть закрытой, нужна выдача приглашений или одобрение регистрации. Расписание сейчас публично по существующему сценарию приложения.
- **Администратор.** Предпочтительно закрепить доступ через `ADMIN_IDS`, а не только изменяемый `@username`. Список администраторов и рабочий токен следует хранить в окружении хостинга.
- **Сон сервиса.** Бот и API работают вместе; сон Render останавливает напоминания и polling. Для надёжных уведомлений потребуется постоянно работающий процесс.
- **Защита браузера.** CSP содержит `unsafe-inline` из-за существующих inline-скриптов и обработчиков. Следующий этап — вынести их в модули и перейти к более строгой политике. Внешние HTTPS-картинки всё ещё разрешены; для закрытой школьной ленты лучше разрешить только загрузки приложения.
- **Рост данных.** Журнал сохраняет тексты изменений и личные действия, включая удалённые комментарии; он доступен администратору. Нужны понятное уведомление пользователям, сроки хранения и регламент удаления. Не следует хранить эти данные бесконечно.

Для визуального развития полезнее сначала сделать быстрым ежедневный путь «открыл → увидел следующий урок и кабинет», затем улучшать ленту и материалы. Большие декоративные анимации, дополнительные вкладки и социальные рейтинги пока усложнят эту задачу.
